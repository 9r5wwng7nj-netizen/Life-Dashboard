# Changelog

The app was built in phases, one module at a time. Each phase was tested by upgrading from the previous version's saved data, so nothing ever needed re-importing.

## Unreleased
- Gift tasks (`giftTasksTick`): ten days before a Family birthday or the anniversary, one task due 3 days before, with saved gift ideas in its notes; `fkit.giftTasks` records each occasion.
- Photo sync. After each good sync, `Sync.photos()` uploads photos the records use (`photoRefs`) that Drive lacks and downloads those this device lacks, `PHOTO_BATCH` (12) each way per sync, as `photo-<id>` files in the app folder (binary multipart upload, `driveUploadBlob`); the rest follow on the next syncs. Nothing is deleted from Drive. `photoMeta` (progress photos) now syncs (`SYNC_SKIP` is empty). Folder listings follow Drive's pages (`driveList`). A failed photo step never stops the records sync; Settings shows photos left and any error.
- Phone width: a long name inside a grid column (for example a USDA food name) no longer widens the page. Grid children get `min-width: 0` (src/app.css), and the phone's recent-food chips truncate.
- Stay signed in to Google. When the link reader Worker holds the app's client secret (`GOOGLE_CLIENT_SECRET`), Drive sync and Find a video sign in with a one-time code and PKCE (`gauthStart`), which the Worker trades for tokens (`/google/token`); each device keeps a refresh token in `ld.sync`/`ld.youtube` and renews the hour by itself (`gauthRenew`, also after a 401). A refused refresh token is dropped and sign-in is asked for. Stopping sync or disconnecting YouTube revokes it. Without the Worker's secret, `/google/ready` says so and the one-hour sign-in is used as before. Sign-in now saves pending changes before leaving for Google.
- The Weekly reset (Tasks → Plan week, renamed; tab id still `plan`): new steps for how last week went (`weekNumbers`, now shared with the Obsidian weekly review's `weekStats`), the nutrition check-in (when there is a plan), the family review (when Family is used) and this week's Obsidian review (`obsWeekly`: the bridge message `openWeekly` or the `obsidian://ld-weekly` link, Library plugin 0.15.0; `tkit.weeks[week].obsReview` records it). Steps number themselves and a ticked step keeps its place. On Sunday (for the week ahead) and Monday, the Today card offers the reset until that week is planned. On a phone, a task row whose only button is the star keeps it beside the title.
- Today card (`dashToday`, first in `DASH_CARDS`): Big 3, due and overdue counts, the next time block, today's reading, the workout (in progress, done, next in a running program, or the last one), tonight's dinner, and, inside Obsidian, teaching dated in the next 7 days. The Library plugin (0.14.0) adds that teaching to `LD_OBSIDIAN.teaching` (`core.teachingSoon`).
- Tidier tasks on a phone. Below `sm`, a task row lets the title take the full width and puts +1/+2/+3, Today and the Big 3 star on one line under it (Block time and Focus stay on wider screens; Focus is also in the editor). *Tidy up* (`staleTasks`, `sweepDraw`) offers tasks 3+ days overdue one at a time (today, tomorrow, next week, Someday, already done, delete, skip); finishing, stopping or *Not today* records `tkit.swept` so the offer waits until the next day.
- Phone bottom bar. Below the `md` breakpoint a bar under the scrolling view holds four sections (`S.bar`, synced, default Dashboard, Tasks, Nutrition, Workouts; Settings → General picks them) with their menu counts, around a **+** button (`quickAddSheet`, `QUICK_ADD`): task (same parser as Tasks), food (today), weight (today), journal entry, prayer request, link. The bar carries the home-indicator space itself; the rest timer and messages sit above it.
- Docs: the guides now describe how the app is used today (the hosted copy, installed on the iPhone and docked in Obsidian, synced through Drive), record the dashboard master plan and Seth's answers in AGENTS.md, add the audit measurements to docs/PERFORMANCE.md, and drop statements that hosting or sync were still to do.
- Quicker on the phone. Dashboard cards can be reordered in the card picker (Up/Down per card; `S.cardOrder`, synced, unknown ids ignored and new cards appended by `dashOrder()`); the default order draws exactly the same HTML as before. Journal and the Media library render 50 items at a time with *Show 50 more* (`pageOf`, `moreBtn`, `ui.more`); search still covers every record. Below the large-screen breakpoint, Nutrition's daily log starts with *Log food* and up to 8 one-tap recent foods.
- Daily copies in Google Drive. With sync on, the first sync of the day also saves a dated copy of the agreed records (`life-dashboard-copy-YYYY-MM-DD.json`) in the same private app folder and thins out old ones: 7 daily, then 8 weekly. Settings & Sync → *Restore from a copy* lists them; a copy can *Add back what's missing* (new `missing` import mode: records, nutrition entries and keys missing on this device are added, nothing present is changed) or *Replace everything* (a sync copy replaces only the synced settings). Any restore schedules a sync. While a copy from the last 7 days exists, the dashboard's weekly backup card stays hidden. A failed copy never stops the sync; its reason shows in Settings.
- Vault health (Library plugin 0.13.1) also leaves out the folders in Obsidian's Excluded files, so imported reference text no longer floods it with broken links, and notes at the top of the vault say so instead of showing "/".
- Vault health (Library plugin 0.13.0). A *Vault health* chip on the Library and a *Check vault health* command open a page listing notes with no type (book chapters excepted), status words outside the usual set, links to notes that don't exist, to-dos still in notes, Granola attendees with no profile, and projects under way that nothing has touched for 30 days. Each has an Open button; to-dos and attendees have their fixing command. Template, reference, left-out and archive folders are skipped. It only reports.
- New sermon can link to an area (Library plugin 0.12.1). Setting *Area for new sermons*: when filled in, each new sermon project gets `area: "[[…]]"`, so it shows in that area note's live Projects list.
- Quick capture (Library plugin 0.12.0). A Capture button on the Library and a *Capture a thought* command open a box (text, then Idea, Illustration, Sermon seed or Quote; Cmd/Ctrl+Enter saves). It makes an inbox note typed by kind, titled from its first words, with `created`, `captured` and, when a passage is mentioned, `scripture`. The `obsidian://ld-capture?vault=…&kind=…&text=…` link does the same, so an iPhone Shortcut (Dictate Text, URL Encode, Open URL) can capture by voice.
- *Move to-dos from notes to Tasks* (Library plugin 0.11.0): one list of every unticked checkbox in notes (not templates, archives, reference text or meetings), grouped by note. Ticked ones go to the docked dashboard linked to their note (the Tasks plugin's 📅 date becomes `due:`, other markers are dropped, a person note's to-dos get that person), and the line in the note stops being a checkbox (*moved to Tasks*).
- Meeting attendees (Library plugin 0.10.0). Granola links attendees by email handle (`[[Jthigpen]]`). A person note's `aliases` list the handles that are theirs; when a meeting arrives or changes, unresolved `people` links that match an alias are replaced with the person's note (`linkAttendees`). Commands: *Link meeting attendees to people* (whole vault) and *Match a Granola attendee to a person*, which adds the alias, creating the profile from the Person template if needed, and relinks. The weekly review lists attendees with no profile.
- Books in the Library (plugin 0.9.0). Classic works open like books: `buildBooks` follows `part_of` links (work-index → parts → treatises → texts, ordered by each parent's Contents links, numbers sorted as numbers), gathers an author's or collection's own writings into a Writings book, and treats a folder whose index note shares its name as a book of chapters. Book covers open a book page (Start/Continue reading, a contents list that opens level by level, chapter topics read from each text, the current chapter marked). Chapters get a reading bar (trail, Previous, Contents, Next, n of N) and the last chapter read is remembered (`reading` in plugin data) for Continue reading on the Library home. The Historical theology shelf shows books only, grouped by collection on its See all page. Meetings: Granola notes without a `type` (they have `granola_id`) count as meeting sources, and a source with a review (`source_meeting`) is shown through its review.
- Filing (Library plugin 0.8.0). *File the inbox* (a command, and a button on the inbox's folder page) lists the inbox notes that would move: to their project's folder when they belong to one, else by `type: folder` rules with `{title}`, `{year}` and `{month}`. The person unticks any to keep, and the moves use Obsidian's rename so links update; nothing is overwritten. *Archive finished projects* moves finished project notes (with their own folder) to the archive, or sermons to the sermon archive. *Add a contents list to this project note* inserts a numbered list of the project's notes (passage, date, status, taught), refreshed whenever the note opens. The weekly review points to File the inbox.
- Weekly review (Library plugin 0.7.0): a Weekly review quick action and commands open this week's review (`<reviews folder>/<year>/<Monday> - Weekly Review.md`, `type: review`, `review_kind: weekly`), creating it if needed. Its top section, between `life-dashboard:auto` markers, is filled in and refreshed: last week's dashboard numbers (`LD_QUERY({ weekStats })`: workouts, tasks finished, reading days, journal entries, weight trend, Big 3, family review, overdue/due/inbox), meetings to process, inbox notes, teaching this week, people to reach and active projects. The reflection below is never touched; a review marked complete isn't refreshed on opening.
- Verse previews (Library plugin 0.6.0). Bible references in reading view (full names, common short forms, 1/I/First prefixes; lowercase words ignored) become links; pointing or tapping shows the verses from the vault's chapter notes ("John 13 (WEB)", `### n` verse headings). The preview offers Open in reader (`{ openPassage }` to the docked dashboard, which calls `rdGo`), Passage note (opens it, moves an archived placeholder back, or creates one in the per-book folder) and Read the chapter. Commands: Insert a Bible passage (a quote callout at the cursor) and Open or start a passage note.
- Library plugin 0.5.1: the Today's note quick action only appears while the Daily notes core plugin is on.
- Taught record (Library plugin 0.5.0): Mark taught on teaching notes writes `taught` entries (`YYYY-MM-DD — Group`) and sets the status. Title cards show where the note was taught and the same passage taught from other notes (`scriptureKey`: book's first letters + chapter). A Teaching record page in the section bar lists each group's history (Teaching groups setting, `(inactive)` marks a resting group), plus finished teaching with no group recorded, each with a Record button.
- Library plugin 0.4.0: the Library works as home. It adds quick actions, a section bar (every shelf, Inbox, All folders) and folder pages (tiles for sub-folders with note counts, notes as rows, a clickable path). Library pages join the tab's back/forward history (`navigation`, `getState`/`setState`), and an option folds the left sidebar away. Person cards show initials, roles and last contact, with no status button; series show Active/Planned. The 0.1.3 title-card fixes (no repeated kind label, outlined status, serif note titles) are restored, after being left off main.
- `@Name` keeps the name in the task title as typed ("Call @dwayne conner" becomes "Call Dwayne Conner", linked to the profile).
- `@Name` in task text links the task to a person (`@fri`, `@today`, months and similar stay dates; a second word is the surname when capitalised or when the two words match a known person). The name resolves to an Obsidian person profile (a unique first-name match counts), then to people already on tasks or in Family. Tasks get `personAt`; inside Obsidian the app sends `{ people: [...] }` for names without a profile and clears the flag, and the plugin (0.3.1) creates them in its People folder from the Person template (`{{title}}`, `{{date}}` filled in). Tasks added elsewhere are handled the next time the dashboard opens in Obsidian.
- People pages (plugin 0.3.0): a person note's title card is followed by their open dashboard follow-ups (tasks whose `person` matches the note's title, first name or aliases, or that link to the note), waiting and overdue marks, and the last finished date, with a tick to complete and a box to add one. The plugin asks through `window.LD_QUERY({ personTasks })`; completing sends `{ completeTask }` and adding sends `{ addTasks }` with a `person`. Mac only, with the dashboard docked; nothing is written to the note.
- Find a video: results are large cards (full-width high-quality thumbnail, bigger title; two columns on wide screens). Videos of 3 minutes or less (Shorts) are hidden in every list, with a Show Shorts switch (`S.ytShorts`, this device only). Search asks for 50 results so a full page remains after Shorts are removed.
- Meetings to tasks: the Library plugin (0.2.0) finds a meeting note's unticked items under Action items / Follow-ups / Next steps / To-do headings (`actionItems`), lets the person tick theirs, and sends `{ addTasks }` to the docked dashboard; sent items are recorded in the note's `tasks_sent` property. The app (`obsAddTasks`) adds them linked to the meeting note, reads dates and tags in the text, takes the area from the meeting's `areas`, marks follow-ups as waiting, and skips items already open from the same note.
- Find a video: YouTube's 404 for an account with no channel (`channelNotFound`) now explains how to reconnect and choose the brand channel; the YouTube sign-in always shows Google's account chooser (`prompt=select_account`). Other YouTube errors include Google's reason.
- Obsidian bridge (app side). Tasks and projects can link to an Obsidian note (`note`; type `[[Note]]` when adding a task; the field is in the task editor and on the project page), shown as a chip that opens it. The Copy for Obsidian buttons become Send to Obsidian. Inside Obsidian (the Life Dashboard Library plugin sets `window.LD_OBSIDIAN`) messages go through `#ld-obsidian=` in the address; elsewhere `obsidian://open` and `obsidian://new` links use the vault name and folder from Settings & Sync → Obsidian (long notes travel by clipboard). `window.LD_FROM_OBSIDIAN` takes the plugin's `sermonPrep` message (queued until saved data loads) and adds a ministry project with a daily think-pray-write task up to the preaching date plus the preaching. - Media Library → Find a video: connects the person's YouTube account (Google sign-in with the read-only `youtube.readonly` permission, through the same OAuth client as Drive sync) to search YouTube and list new videos from subscriptions (up to 50 channels), the person's playlists and liked videos, and a channel's latest uploads. - Recipes & Meals: Hosting & meal trains is now Hosting. Bringing and receiving meal-train meals is no longer offered; saved `bring` and `receive` records are kept but not shown.
- Link reader: a Cloudflare Worker (`reader/`) fetches pages for the app. Saving a recipe link fills in the whole recipe (ingredients, steps, servings, time, photo); saving an article keeps its title, author, picture and a readable copy; TikTok links get their caption. Import a recipe gains a web-address box. A pasted caption with an ingredient list also becomes the recipe's ingredients and steps, for Facebook and Instagram, which cannot be read.
- Plan my week (Recipes & Meals → Meal plan): choose days, meals, people, budget and cooking time; it picks a varied week from the user's recipes and a 34-recipe ready-made library (`RECIPE_LIBRARY`, estimated costs and nutrition), shows the estimated total against the budget, allows swapping or dropping any meal, and on Looks great fills the meal plan, copies used library recipes into the recipe box once, and builds the grocery list.
- Touch screens: buttons and section tabs are at least 40px tall (small buttons 36px, chips 34px), tick boxes 20px, and no text is smaller than 12px. CSS only, under `@media (pointer: coarse)` in `src/app.css`.
- Add from a link: a header button opens a sheet for a pasted link or text, suggests Media library (with the type: video, podcast, sermon, article, book), Recipe or Task, and files it there. Android's share menu opens the same sheet (manifest `share_target`).
- Tasks → Today: tasks due today or overdue have Push +1 / +2 / +3 buttons that move the task that many days from today.
- Barcode scanning works in Safari on iPhone (and Firefox): when the browser has no built-in barcode detector, the camera frames are read by the bundled ZXing library (`vendor/zxing/`).
- When a task is added from text, anything in (parentheses) is left out of the title and saved in the task's notes, and is not read for dates, tags or people. This applies wherever tasks are created from text, including templates.
- The add-task box can add several tasks from one entry: `|` separates tasks, and `+1` / `-1` (or `+1w`) date a task relative to the first one. Later tasks inherit the first task's person, project and tags. Undated tasks are flagged in the preview and land in the Inbox. A Repeat tick box beside Add (daily, weekly, monthly, chosen days of the week, or a custom interval; the days can also be changed in the task editor) applies to every task in the entry, and the rules can be shown under the box.
- Task and project editors keep a custom repeat interval (such as every 3 days) when saved; before, saving reset it to every day.
- Projects can repeat (weekly, every 2 weeks, monthly, yearly). The next round is created once, when the due date arrives or every task is finished, with each task's date moved forward. A repeat can also be chosen when using a template.
- Tasks has a Select mode for changing many tasks at once: status, due today/tomorrow, Someday, area, project, or delete.
- Start-here tour for new users (a card on the dashboard, and under Help & what’s new in the menu), and a what’s-new message with slides after each update, driven by the `RELEASES` list.
- Menu items show a count for what needs attention today (tasks due or overdue; Scripture reading and memory verses; no food logged or weigh-in; no journal entry; no dinner planned; the weekly family review). Daily checks look at today only and stay quiet until that part of the app has been used, with a dot on the menu button on phones. Counts live in one `NAV_COUNTS` registry with an entry for every menu item.
- Tasks → Templates includes a built-in library of 25 templates that any user can use or copy into their own list. New installs no longer start with three ministry templates; existing template lists are unchanged.
- Tasks stay in the Inbox until they have both a due date and an area or project. Someday and waiting-on tasks are unaffected.
- Fields use 16px text on touch screens so iPhones no longer zoom in when one is tapped.
- Generic wording for sharing: family exports are titled “Family Rule of Life”, or “<Family name> Family Rule of Life” when the new optional Family name setting is filled in. Placeholders no longer mention a personal vault or sermon series, and two local churches were removed from the default sources list for new installs (existing lists are unchanged).
- Scripture memory practice: type the first letter of each word through three steps (Read, Recall, Master), with 90% needed to pass. Reviews are graded by typing; saying a verse aloud and grading yourself is still available. Practice earns XP, levels, a daily streak and badges, shown on the Memory tab and the dashboard. Adds one collection, `memkit`; existing memory verses are unchanged.
- Sync safeguards: every sync first reloads what is saved on the device, so a second tab left open cannot sync an out-of-date view over newer data; and a sync that would remove more than 10 records pauses until it is confirmed.
- Device sync through a private Google Drive app folder: three-way merge of records and basic settings, a header sync button and controls in Settings & Sync. Each device turns it on in Settings & Sync. Photos, API keys and downloaded libraries do not sync yet. No stored data changed; sync adds one localStorage key (`ld.sync`) and one device-local entry (`sync.base`).
- Mobile phase started (Seth, 2026-10-12): the app has a web manifest, home-screen icons, safe-area padding and a service worker (`sw.js`) so a hosted https copy installs on a phone and reopens offline. The `file://` copy never registers the worker and behaves as before. No stored data changed.
- The repository is public and GitHub Pages hosts the app at https://9r5wwng7nj-netizen.github.io/Life-Dashboard/. Sync is not set up yet.
- Journal Focus is a named keyboard-contained dialog with an inert background, visible focus, Escape cleanup and return focus. Journal/family detail controls have meaningful names; task-board titles are keyboard-editable and completed tasks retain readable contrast.
- Food lookups and Bible requests have bounded response/body waits and offline/unreachable/invalid-response recovery messages. Public-service checks and remaining manual steps are documented without claiming service availability or screen-reader certification.
- Backups containing existing MacroFactor name|unit food identifiers can be restored; unsafe identifiers are still rejected and saved IDs are not rewritten.
- CI now exercises populated views, common editing/search workflows, recurring tasks, imports/backup roundtrips and performance probes in isolated Chromium contexts.
- Startup reads the 51 saved collections in a single transaction and stops safely if that read is interrupted.
- Projects and People group tasks once per view instead of rescanning all tasks per project/person. Photo loads are deduplicated and unused object URLs are released without deleting saved photos.
- A repeatable isolated-browser performance probe checks large synthetic task lists, startup reads and photo cache lifecycle.
- Long section-tab strips remain inside the main view at medium desktop widths instead of widening the whole page.
- Shared accessibility fixes add associated form labels, dialog focus management, keyboard navigation, live announcements, visible focus indicators, reduced-motion support and improved small-text/button contrast.
- Accessibility regression checks cover the main views/sections in light/dark mode and common editing dialogs.
- Backup import validates the file before modifying data and commits records/photos in one IndexedDB transaction, preserving existing data on failure.
- External links and media embeds reject unsafe URL schemes and lookalike service hosts; structured article/recipe clips validate their types.
- Podcast callback scripts run in an isolated sandbox, and link previews use ordinary JSON requests.
- Backup format v2 includes personal photo files as well as their metadata. API keys and re-downloadable reference libraries remain excluded.
- Legacy v1 backups still import safely and preserve photos already stored in the destination browser.
- “Erase all data” now clears records, photos, downloaded libraries, settings and API keys from the browser.
- Tailwind styles, Lucide icons and SheetJS are pinned and served locally; startup and spreadsheet imports no longer execute CDN-hosted dependency code.
